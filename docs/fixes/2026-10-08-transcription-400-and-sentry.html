SayCopy: why the preview still returns HTTP 400

Prepared for Tarek · October 8, 2026

The audio format caused the reproduced failure

The latest completed previews are iOS 1.1.1 build 11 and Android 1.1.1 build 5, built from commit 388868b. Both contain the previous Auto-detect change to MAI-Transcribe 1.5. The update reached the previews; its provider compatibility check was incomplete.

SayCopy records and uploads M4A audio. Using a short synthetic speech fixture with the same sample rate, channel count, codec, bitrate, JSON request shape, and mandatory zero-data-retention routing as the app, the live MAI route returned HTTP 400. Converting the same fixture to WAV succeeded. Whisper Large V3 Turbo accepted the original M4A.

The previous tests used mocked provider responses and checked catalog availability. Those checks could not establish that the provider would decode native recordings. The screenshot matches the reproduced Auto-detect failure; the exact failed device request cannot be inspected retroactively because the older app has no Sentry integration.

The format diagnosis is consistent with OpenRouter’s provider-specific format guidance and Microsoft’s MAI audio prerequisites.

The fix

  • Auto-detect uses openai/whisper-large-v3-turbo, already the recommended explicit-language model and now verified with real M4A requests.
  • The source-language field remains omitted for Auto-detect. Zero-data-retention routing remains required.
  • Saved explicit-language preferences stay saved. The picker omits MAI-Transcribe 1.5; an existing explicit MAI preference produces an actionable message before uploading, directing the user to Whisper or Auto-detect.
  • App labels, setup, support, and privacy pages describe the same behavior.

For the currently installed October 5 preview, choose a specific Recording language and the Recommended transcription model in Settings. That uses the compatible Whisper path while the corrected preview is pending.

Permanent rule: every error goes to Sentry

The rule is recorded in AGENTS.md and a requested memory update. Handled exceptions now use a centralized reporter across recording, temporary-file deletion, provider retries, cleanup fallback, translation fallback, history, settings, tags, clipboard, sharing, external links, and system speech. The SDK initializes before app modules and includes a render/startup boundary and native crash handling. Expected cancellation is excluded.

Error sampling is 100%. The same error object bubbling through several layers is reported once; distinct failures remain eligible for reporting. The SDK’s consecutive-event deduplication is disabled. ESLint rejects silent catch handlers unless they rethrow for upstream reporting.

Application reports use fixed operation labels, categories, HTTP status when available, release/build identity, and stack locations. A final allowlist reconstructs JavaScript events and removes original messages, user details, request bodies and headers, breadcrumbs, contexts, props, frame locals, and arbitrary extra fields. API keys, audio/base64, transcripts, translations, clipboard contents, tags, SQL parameters, and raw provider responses are excluded. Screen capture, session replay, console breadcrumbs, performance tracing, and telemetry request headers are disabled.

Native crash handling may include OS/device technical metadata. Android permits the ordinary network-state permission needed for crash-report connectivity. The Expo plugin and Metro configuration support source maps. EAS environments are explicit, and the build worker refuses to compile without the SayCopy DSN, organization, project, and upload token. Worker-only secrets do not block local EAS config resolution.

Reference: Sentry’s Expo setup and Sentry’s data-scrubbing guidance.

Validation

  • Expo Doctor: 20/20 checks passed after updating Expo, expo-asset, and expo-sqlite to current SDK patches.
  • Both iOS and Android Hermes bundles exported with source maps.
  • Website HTML and all internal links validated.
  • Live requests through the actual client, provider, and transcription flow succeeded in English, Arabic, and Spanish. English and Arabic also completed Light cleanup; Arabic remained Arabic. The synthetic results were saved through an injected test history repository.
  • Live text translation through the actual provider succeeded from English to Spanish.
  • Regression coverage verifies reporting on cleanup fallback, best-effort deletion, asynchronous speech failure, HTTP diagnostics, privacy scrubbing, cancellation, duplicate propagation, and build configuration.

Live audio tests used generated synthetic speech, never personal recordings. The local test repository is a substitute for device storage. These results do not establish microphone behavior, native binary compilation, three-minute recordings, network interruptions on a phone, or physical-device Sentry delivery.

Remaining delivery gate

Sentry is implemented and locally tested, but not live in an installed preview. The Composio Sentry connection is absent, the available local authentication token is rejected, browser access requires sign-in, and the EAS preview environment contains no variables. A SayCopy Sentry project/DSN and valid source-map upload token must be configured before generating the new preview. Event receipt and source-map symbolication must then be verified, followed by physical-phone transcription checks.

Do not reinstall the old build 11 expecting this fix. A new, uniquely identified preview must be generated from the corrected commit. Store submission/publication has not been performed.
