Why the request can fail

Auto-detect used openai/gpt-4o-transcribe while every request required zero-data-retention routing. The public OpenRouter catalog and zero-data-retention endpoint list checked on October 4 contained no eligible route for that model. This is a confirmed routing mismatch and a likely explanation for the screenshot.

The screenshot contains no HTTP status or private request log, so the exact failed request cannot be conclusively diagnosed from it.

Sources: OpenRouter zero-data-retention endpoints, GPT-4o Transcribe endpoints, transcription routing documentation.

What changed

  • Auto-detect now uses microsoft/mai-transcribe-1.5, which has an eligible Azure route and supports automatic language identification. Your preferred explicit-language model stays saved.
  • Zero-data-retention routing remains required.
  • Rejected requests show safe explanations and HTTP status numbers for invalid requests, denied access, missing endpoints, and oversized recordings.
  • Bottom tab labels use a slightly smaller font, more horizontal space, and single-line fitting.
  • Setup and support documentation use the same model names and explain troubleshooting.
  • Expo was updated from 57.0.25 to the expected 57.0.26 patch so the SDK validation check passes.
