SayCopy preview review and Google Play plan

Prepared September 25, 2026 · app baseline 6d35a14 · version 1.1.1

The iOS internal preview was requested from EAS using the preview profile and this exact clean commit. Installation and device checks remain to be done after the build completes. No store submission is part of this preview.

Review of the recent changes

  • The history repository now filters and sorts in SQLite instead of loading every table and filtering in JavaScript. This should help as history grows.
  • Audio uses 16 kHz mono at 32 kbps, reducing upload size; the new three-minute limit and 90-second transcription timeout need a real-device test with a long recording and weak network.
  • Transient OpenRouter errors retry after short delays. A dropped connection after the provider accepts a request may cause a second request and possible duplicate model charges. Consider showing retry progress and checking whether request identifiers or provider behavior can make repeats safer.
  • The new Translate tab adds speech input, read-aloud, saved translations, and language selection. Its saved-items loader currently fetches the entire history before showing the latest 20 translations; a database-level filtered, limited query would scale better.
  • Typecheck, lint, Expo Doctor, and the app's 263 tests passed. The default Jest command also scanned a nested Claude worktree; this review branch excludes nested worktrees.

iOS preview acceptance

  1. Confirm the EAS build succeeds, note its build ID and install link, and verify the archive records commit 6d35a14 and internal distribution.
  2. Install on the provisioned iPhone. Test microphone permission, a short and a three-minute recording, transcription and Light cleanup, typed and spoken translation, read-aloud, history and tags, relaunch persistence, and clipboard/share.
  3. Test missing API key, invalid key, offline use, and interrupted uploads. Record any user-visible wording or timing issues before choosing a release candidate.

Google Play path

  1. After iOS feedback is addressed, build an Android internal preview APK from the chosen release candidate and test on an Android phone, including microphone behavior, back navigation, keyboard, clipboard/share, and upgrade from the installed Play version if one exists.
  2. Check the current Play Console app and track state, listing assets, policy forms, Data safety, content rating, target audience, app access, and reviewer credentials. The July release record is a starting point but its version and open items must be refreshed against the Console.
  3. Build a signed production Android App Bundle with a new version code. Verify package com.altitudeinfosys.saycopy, version, permissions, signing, and target API level. Google currently requires API level 36 for new phone apps and updates submitted after August 31, 2026.
  4. Upload the AAB to an internal testing release, install the Play-delivered build, repeat the acceptance tests, and resolve Console warnings.
  5. Prepare the production release and rollout choice, then review the exact AAB, listing, declarations, and release notes before sending it for review.

References: Google Play target API requirements and release and testing tracks.
