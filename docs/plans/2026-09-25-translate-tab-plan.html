Translate Tab Plan

Date: 2026-09-25

Goal

Add a dedicated Translate tab that works like a small Google Translate for language learning. You type or speak a phrase, choose From and To languages (with a swap button between them), hear the result read aloud, and tap Save to keep it in on-device history with tags for later review.

Decisions (confirmed 2026-09-25)

  • Storage: on the phone only, using the existing SQLite history and tags. No accounts or cloud sync.
  • Saving: the Translate tab saves only when you tap Save, where you can also add tags. The Record tab keeps saving every transcription automatically.
  • Read aloud: on-device voices through expo-speech. Free, instant and works offline.
  • Languages: the current three plus French, German, Italian, Portuguese, Chinese, Japanese, Korean and Hindi (11 total).
  • Record screen: its Transcribe/Translate switch is removed, so Record becomes transcribe-only and all translation lives in the new tab.
  • Navigation: bottom bar becomes Record · Translate · History · Settings.
  • Model recommendations: Settings shows how many of the app's languages each speech-to-text model supports, and recommends the models with the widest coverage.

Screen layout

  1. Language bar: From picker, a ⇄ swap button, then the To picker. From includes Auto-detect; swap is disabled while From is Auto-detect. Swapping also moves the current result into the input box so you can translate back. The last-used pair is remembered.
  2. Input: a multi-line text box with a microphone button. Speaking records up to 3 minutes and puts the transcript into the box, so you can correct it before translating. Tapping Translate or the keyboard's Done key runs the translation. It doesn't translate while you type, which would add a paid request per keystroke.
  3. Result card: the translation with Copy, Listen (🔊, in the To language's voice) and Save. Save opens the tag editor the app already has and stores a translate history item with those tags.
  4. Saved list (below the result): the most recent saved translations, with tag chips to filter them. Tapping an entry loads it back into the screen; each entry also has a Listen button for quick review.

Implementation, in two pull requests

PR 1: More languages

  1. Add the eight languages to src/domain/languages.ts with their OpenRouter speech codes (fr, de, it, pt, zh, ja, ko, hi) and speech-voice locales for read-aloud.
  2. Record verified speech-to-text support for them in src/domain/transcriptionModelLanguages.ts. Models without verified support keep the existing “support unverified” warning.
  3. Make the translation prompt label and the settings and history validation accept the new languages. Existing saved data needs no migration, since languages are stored as text.
  4. Show language coverage in Settings:
    • A badge on every transcription model: “Supports 11 of 11 languages”, or “Supports 6 of 11 — no Arabic, Chinese, Japanese, Korean, Hindi”.
    • A Best language coverage group at the top of the recommended models, sorted by verified coverage. Ties go to the faster or cheaper model.
    • When the selected recording language isn't supported by the current model, a one-tap suggestion to switch to the best-coverage model for that language.

PR 2: Translate tab

  1. Split translation from saving. Add a translate-only processor that returns the result without writing history, plus a save action that calls createHistoryItem with the chosen tags. The Record screen's auto-save flow is left unchanged.
  2. Add src/screens/TranslateScreen.tsx with small components: language bar with swap, input with microphone, result card and saved list. Reuse LanguageSelect, TagEditor, the audio recorder controller and the history repository. Show a Loading state, and let retries from the OpenRouter client happen quietly.
  3. Add expo-speech (via npx expo install) behind a small speech adapter. It picks a voice for the To language, stops earlier playback before starting new, and shows a clear message when the phone has no voice for that language.
  4. Store translateSourceLanguageId and translateTargetLanguageId in settings.
  5. Remove Translate mode from RecordScreen.tsx, along with ModeSegmentedControl, its manual-text panel and the defaultMode setting. Old translate items stay visible in History.
  6. Add the tab to App.tsx. The hardware back button still returns to Record.

Testing

  • Unit tests: coverage counts and ordering of the Best language coverage group, translate-only processor (no history write), save with tags, swap behavior (including Auto-detect disabled) and the speech adapter (voice choice, missing voice).
  • Screen tests: type → translate → save with tags → appears in the saved list; mic → transcript fills input; tag filter; tapping a saved item restores it; Record has no Translate switch.
  • Full suite, typecheck, lint and Expo Doctor on each PR.
  • Manual device check (you run locally): mic permission, read-aloud voices on iOS and Android for Spanish, and keyboard behavior on small screens.

Documentation

  • website/support/index.html: a Translate tab section (save and tags, Listen, languages, why Auto-detect can't be swapped), and updated wording now that Record is transcribe-only.
  • website/setup/index.html: mention the Translate tab and the new languages.
  • Use the same labels in the app and on the website: Translate, From, To, Swap languages, Listen, Save, Tags.

Preview builds

The cloud session has no Xcode or Android SDK and no Expo account credentials, so preview builds run from your machine. From an up-to-date main:

  • iOS Simulator (fastest loop): npm ci && npx expo run:ios
  • Android emulator or device: npx expo run:android
  • Installable internal build using the existing preview profile in eas.json: eas build --profile preview --platform ios (or android for an APK). Add --local to build on your Mac instead of EAS servers.
  • Adding expo-speech in PR 2 is a native module, so after that PR you need a fresh native build; Expo Go or an older dev build won't have it.

Out of scope for now

  • Cloud sync and accounts.
  • Flashcards and spaced-repetition review, a natural follow-up once saved phrases exist.
  • AI voices for read-aloud.
  • Live translate-as-you-type.
